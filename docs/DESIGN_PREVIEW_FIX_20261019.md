# 設計画面で左右キーを押したときの配置位置を保持

2026-10-19。配置前の兵装がマウスに追従しているとき、左右キーで向きを変更すると、マウス自体は動かず兵装だけが左端へ移動する問題への修正。

## 原因と修正範囲

識別済みゲームの設計ハンドラーは、左右キーの方向変更後に画面上のカーソル位置を取得し、そのまま内部プレビュー更新コマンド `0x7FA` へ渡していた。受け側の `0044E0F0` はゲーム内座標を期待し、Yが30未満または301以上なら配置用のX/Yをゼロへ戻す。全画面の原点が0のときは同じ座標になるが、本体を移動したウィンドウでは一致しない。

今回は左右キー経路の `0044E925`（RVA `0x4E925`）のEDIへの関数読込みだけを専用の座標取得関数へ変更する。左右の呼出しはこの関数を共有する。POINT取得後、WINDOWINFOで求めた本体クライアント原点を引いてから、元の方向変更・プレビュー再計算を続ける。マウスを移動したり、部品の保存座標を強制固定したりする処理は追加しない。

対象は既存の名前・タイムスタンプ・SizeOfImage識別を通過したビルドの通常ウィンドウモードだけ。変更する6バイトに加え、左右それぞれの呼出しとコマンドの元命令を一括照合してから適用する。命令が違えば何も変更しない。書込み許可・命令キャッシュ同期・保護復元と巻戻しは既存処理を共有する。

`FixDesignPreview=0` で個別に無効化できる。省略時は有効。`WSC1CompatGetStatus` の `0x2000` は、この設計用補正の照合・導入失敗を示す。戦闘用のマウス入力・描画カーソルの補正とは別設定とする。

## 検証

Win32 ReleaseビルドとCTest 3/3成功、計134項目。

追加試験は、元の画面座標が配置範囲外になる条件、補正後の同じクライアント座標、繰り返し変更、移動後・負の画面座標、ネイティブAPI失敗を確認する。また、分離した実行可能メモリに実際のx86命令を導入してcallback呼出しとstdcall ABIを検査する。右側コマンドの不一致、保護変更失敗、キャッシュ同期失敗で書換えや半適用を残さない経路も確認した。

DLL SHA-256: `f30929a9c9576761ae82967d163b37b31458d490717832bdfdfa771c9506f412`。

検証用 `trial_007_issue_audit` の旧DLLを別の解析フォルダーへ保全し、新DLLだけを交換する。ゲーム本体、DRM、音源、設定、セーブ、配布Releaseは変更しない。

この試験は元の設計画面での最終的な目視確認を代替しない。交換後、同じ兵装を選んで左右キーを押す、配置を確定する、本体を移動して繰り返す、という実機確認が残る。クリックする変更ボタン・上下キーは今回特定した左右キー経路と同一とは断定していない。
