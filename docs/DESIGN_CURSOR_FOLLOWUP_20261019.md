# 設計画面の部品プレビューと復帰時音声の追跡

続く調査で、描画カーソルとは別に左右キー後の配置用座標を誤って渡す経路を特定した。直接の配置位置修正は [DESIGN_PREVIEW_FIX_20261019.md](DESIGN_PREVIEW_FIX_20261019.md) を参照。以下は先行する描画カーソル適用範囲の修正記録。

2026-10-19。PR #5 の `7e00b6f` を入れた検証用複製で、利用者から「兵装の高さ・向きを変えると左端へ移動する」「非アクティブ化から戻るとCDを読みゲームが停止する」という報告があった。

## 実行時に確認したこと

- 対象は `trial_007_issue_audit` の識別済みBCS.ICD。新しいDLLと2か所のカーソルパッチが実際にロードされ、MCI IATも専用DLLを指していた。
- 公開状態のフック失敗ビットは0。導入失敗やIAT未交換が原因という仮説は棄却した。
- 設計画面で、16トラック・音声開始47749・終端258418・TMSFのWAVデバイス1を確認した。既存音源はネイティブ検査も成功。
- 設計画面の状態では、既存の戦闘カーソル参照先 `app+0x8c -> +0x10aa` はnullだった。
- 再現後の短時間採取ではUIスレッドはメッセージ待機経路にあり、最終採取時は非アクティブだった。これは戦闘中のCD待機やデッドロックの証拠ではない。
- 利用者から「音声読み込みのためにゲームは止まらなかった。戦闘画面だけかもしれない」と訂正があった。設計画面での音声起因停止を確定事項として扱わない。戦闘復帰時の停止は未確認。

コード・DRM・セーブへの実行時書込みはしていない。状態採取時にはUIスレッドのコンテキストを短時間取得し、必ず即時再開した。17件のセーブ・設定・旧DLLを解析フォルダーへ別途保全した。

## 座標補正の適用範囲を修正

従来の `SpriteCursor` は、識別済みの描画呼出しを通るたび、どの画像オブジェクトかを区別せず本体のクライアント原点を減算していた。戦闘用の補正が、設計用など他の画像にも及ぶ実装だった。

修正では、照合した命令位置で保持されているESIを描画オブジェクトとして受け取る。ゲームの戦闘カーソル参照と同一のオブジェクトに限ってクライアント座標へ変換する。他オブジェクトや戦闘カーソル未生成・破棄中は、元のデスクトップ座標を返す。グローバルUSER32フックや設計・部品データの強制変更は追加しない。

これは戦闘以外へ補正が及ぶコード上の問題を修正するもの。利用者環境で報告された設計画面の症状が解消するかは、交換後の再確認が必要。

## 検証と候補DLL

Win32 Releaseでビルド、CTest 3/3成功、計120項目。追加した8項目は以下を確認する。

- 設計用画像は戦闘オブジェクトが存在してもデスクトップ座標のまま。
- 戦闘カーソルだけ本体原点を引く。
- 戦闘カーソル未生成、アプリ破棄中、ネイティブAPI失敗時の動作。
- 実際のx86ブリッジでESIが渡され、stdcallのスタックが維持されることを設計・戦闘の両方で確認。
